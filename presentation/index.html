Architecture schools train students to defend every decision on a section drawing. Then we send them into practice, where buildings ship with apps, kiosks, dashboards, and access systems, and expect the digital layer to be someone else's problem.

The fracture nobody talks about in studio

Third-semester M.Arch students at REVA already read program, circulation, materiality, and context. They present with conviction. They respond to jury criticism. They think in evidence: spatial evidence.

Human–Computer Interaction asks the same discipline of them, but the evidence is different: interview transcripts, task-completion rates, findability scores, accessibility audit results, iteration logs. Not weaker evidence. Different evidence.

REVA's own program outcomes already anticipate this shift. PO4 calls for data-driven design decisions. PO2 asks students to analyze user needs and contextual data alongside environmental parameters. The syllabus for M25DA304D (spatial interaction, VR/AR, accessibility, usability testing) isn't a detour from architecture. It's an extension of it.

From spatial program to interaction program

After 16–20 years across SAP, Cisco, DTALK, Rupeek, and MoneyView, plus an MS in Computer Software Engineering from BITS Pilani, I've learned one thing that transfers everywhere: complexity doesn't become simple through styling. It becomes simple through structure.

At Cisco, I worked on the SRM platform: users got lost not because the UI was ugly, but because the program was wrong. At Rupeek, I built a research lab and watched how Indian households navigated gold loans across branch, phone, and screen: one journey. At MoneyView, trust and clarity are measured in drop-off rates and task completion, not opinions.

Architects already do this with space. I teach them to do it with the digital layer.

Six directions where architecture and UI/UX actually merge

Each project starts from a building or site, not a blank app brief.

01

Wayfinding as spatial IA

Hospital · Campus · Transit

Map physical circulation, then design a digital navigation layer. Validate with card-sort or tree-test (n≥8). Measure findability before and after.

02

Smart environment control

Co-working · Residential · Hospitality

Interface for lighting, booking, access, or climate, tied to a floor plan. Task-completion testing + WCAG 2.1 AA heuristic audit.

03

Community service interface

Housing · Civic · Healthcare access

Service-delivery flow for the community the building serves. 5 stakeholder interviews, journey map, pain-point scoring.

04

Cultural hybrid experience

Gallery · Heritage · Exhibition

AR overlay, audio guide, or interactive exhibit layer. Think-aloud usability testing with disengagement mapping.

05

Collaborative AEC tool

Workflow · Multi-stakeholder review

Reimagine how architects, clients, and consultants review projects. Benchmark against 3 existing tools, test your prototype.

06

Accessibility-first public UI

Government · Transit · Public amenity

Inclusive interface for diverse abilities, languages, literacy. Automated + manual audit. Test with assistive technology.

Task-based learning with a data contract

I don't teach HCI as theory with projects attached. I teach it as a sequence of tasks. each week produces evidence. Every deliverable answers: what did you observe, what did you measure, what changed?

Wk 1–2
Context + Users

5 interviews or 3 contextual observations → synthesized insights

Wk 3–4
Structure

Site map + task flow, validated with card sort / tree test (n≥8)

Wk 5–6
Visual + Interaction

Design system draft, heuristic self-audit

Wk 8
Mid-semester jury

Research report + design recommendations with evidence (25%)

Wk 9–11
Working prototype

Clickable Figma or HTML/CSS/JS frontend: full flow, not hero screens

Wk 12–13
Usability test

n≥5 users, success rate + time-on-task documented

Wk 14–15
Iterate from data

Before/after comparison. What the numbers changed.

Wk 16
Final jury

Working prototype + portfolio case study (35% + 10%)

What students actually ship

  • A working frontend: clickable prototype or browser-ready HTML/CSS/JS build
  • A research appendix: interviews, test results, iteration log
  • A portfolio case study: problem → evidence → design → test → outcome

If it doesn't work when a stranger interacts with it, it's not finished.
