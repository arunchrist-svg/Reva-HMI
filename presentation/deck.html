05: MY METHODOLOGYEVIDENCE → EXPERIENCE

The Evidence-to-Experience framework

Every design decision starts with evidence.
Not opinion.

This is my assessment and teaching methodology: collect evidence, make an evidence-backed decision, measure whether it worked, then iterate.

  1. 01

    Observe

    Research real users. Five interviews or three contextual observations. What do they actually do?

  2. 02

    Hypothesize

    Turn research into a clear problem statement. What is the core issue, and why is it unresolved?

  3. 03

    Build

    Create a prototype: Figma, HTML or paper. Make the hypothesis tangible; polish comes later.

  4. 04

    Test

    Put it in front of 5+ users. Watch what breaks. Measure success rate and time-on-task.

  5. 05

    Iterate

    Let the data decide what changes. Build the next version, and test again.

Why this works for architects

Drawings are hypotheses tested against real buildings. HCI applies the same rigor; the evidence comes from users, not codes.

Core belief: Evidence always overrides opinion, even your own.

11: PROJECT BRIEFHEALTHCARE SPATIAL UX

LESSON PLAN · HOSPITAL HMI STUDIO

Hospital Navigation &
Patient Check-In Kiosk.

Designing an accessible, low-stress spatial digital interface for tertiary hospital lobbies.

The Brief

Patients and visitors arriving at large medical centers experience high cognitive load, disorientation, and acute anxiety. Students will design a dual-layer HMI system: an interactive physical lobby kiosk connected seamlessly to a mobile wayfinding interface.

The Studio Rules

  1. 01No Design Without Evidence. Every wireframe layout must directly reference user research.
  2. 02Data Over Opinion. Juries evaluate measurable metrics — completion rates, task time, error rates — not personal aesthetics.
  3. 03The Stranger Test Mandate. If a non-designer stranger cannot complete check-in without help, the project is not finished.
12: PHASE 01RESEARCH & SPATIAL AUDIT

PHASE 01 · CONTEXTUAL EVIDENCE

Observing lobby friction
in high-stress environments.

Mapping physical foot traffic and patient anxiety before building interfaces.

30% Input · Lectures

  • Cognitive Load in High-Stress Contexts. How pain, panic, and age affect visual parsing and decision speed.
  • Spatial Mental Models. How visitors translate physical building layouts into mental directional maps.
  • Field Research Protocol. How to observe lobby workflows and conduct non-leading contextual interviews.

70% Workshop · Task

  • Fieldwork. Visit a hospital lobby or outpatient center. Observe 5 real check-in or wayfinding interactions.
  • Friction Logging. Note exact points of confusion, signage failures, and reliance on reception staff.

Assignment 01 · The Spatial Friction Map

Deliver a composite floor plan overlaid with physical traffic flows, patient emotional drop-off points, and direct quotes from observation sessions.

Grading Checkpoint 01

Pass: Minimum 3 documented friction points with direct observational timing or quotes. Student defends why the physical environment fails before proposing a digital solution.

13: PHASE 02TASK ARCHITECTURE

PHASE 02 · SYSTEM ARCHITECTURE & TASK FLOW

Defining the task hierarchy
before visual design.

Stripping away UI clutter to focus entirely on task completion.

30% Input · Lectures

  • Progressive Disclosure. Showing only the immediate next action to prevent cognitive overload.
  • Accessibility Baseline (WCAG 2.2 AAA). Touch target sizing, glare reduction, high-contrast visual hierarchy.
  • Cross-Device Handoff. Architecture for transferring directional maps from a public kiosk to a personal mobile device via QR or SMS.

70% Workshop · Task

  • Task Mapping. Map the 3-step check-in loop: Identity Verification → Appointment Confirmation → Route Generation.
  • Paper Prototyping. Draft 1-minute paper screen layouts to test layout order.

Assignment 02 · Hypothesis Statement & Wireframe Flow

Formulate a testable hypothesis and deliver low-fidelity screen flows for both the kiosk and mobile phone. Format: "By replacing menu lists with a 3-button progressive kiosk interface and mobile QR handoff, check-in time will drop below 45 seconds with zero staff intervention."

Grading Checkpoint 02

Pass: Hypothesis includes target time-on-task metrics from Phase 1 data. Screen flow shows max 3 actions per screen.

14: PHASE 03INTERACTION MECHANICS

PHASE 03 · INTERACTIVE PROTOTYPING

Building the 1:1 scale
interactive prototype.

Converting paper layouts into functional, high-fidelity HMI screens.

30% Input · Lectures

  • Public Screen Ergonomics. Touch height zones for standing, seated, or wheelchair-bound users.
  • Spatial Typography Scale. Type sizing and contrast optimized for readability from a 3-foot distance.
  • Error Prevention Patterns. Designing confirmation steps to prevent wrong department selection.

70% Workshop · Task

  • Figma / HTML Sprint. Build a 1:1 scale, interactive 1080×1920 vertical kiosk prototype.
  • Mobile Prototype. Build the responsive mobile wayfinding screen received after scanning the kiosk QR code.

Assignment 03 · The Functional Frontend

Deliver a fully interactive prototype ready for live user testing on a vertical monitor or large touch surface.

Grading Checkpoint 03

Pass: 100% accessibility compliance — minimum 48×48dp touch targets, contrast ratio 7:1. Technical audit confirms high-glare readability and touch ergonomics.

15: PHASE 04EMPIRICAL TESTING

PHASE 04 · THE STRANGER TEST

Putting the interface in front
of 5 real strangers.

Measuring performance with hard data instead of personal assumptions.

30% Input · Lectures

  • Unbiased Usability Protocols. Facilitating Think-Aloud tests without prompting or helping the subject.
  • Quantitative Data Logging. Tracking Task Success Rate (%), Time-on-Task (seconds), and Misclick Counts.
  • The 5-User Rule. Why testing with 5 users reveals 85% of core usability flaws.

70% Workshop · Task

  • Live Testing Lab. Set up a kiosk testing station in the studio.
  • Testing Execution. Each student runs 5 usability tests with non-architect strangers — targeting senior citizens or non-tech-savvy users.

Assignment 04 · Usability Test Log & Failure Report

Document all 5 testing sessions with timestamped video snippets, quantitative metric tables, and failure points.

Grading Checkpoint 04 · Data Audit

Task Completion: 100% unassisted  ·  Time-on-Task: under 45 sec  ·  Misclick Count: <1 wrong tap per session. All three required.

16: PHASE 05DATA-DRIVEN REFINEMENT

PHASE 05 · EMPIRICAL ITERATION

Fixing interaction failures
driven by user data.

Refining the interface based strictly on empirical evidence from Phase 4.

30% Input · Lectures

  • Severity Triaging. Ranking UI bugs by critical path impact versus minor visual preference.
  • Design Jury Defense. Framing final presentation arguments around performance deltas and user evidence.

70% Workshop · Task

  • UI Redesign. Redesign every interface element that caused confusion or delay during testing.
  • Verification Run. Test the updated prototype with 2 new users to verify completion time dropped and errors reached zero.

Assignment 05 · The Final Working Argument

Compile the complete 3-part portfolio deliverable ready for final presentation and jury evaluation.
